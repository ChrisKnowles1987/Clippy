# Design Notes

## Project Philosophy

Clippy is not intended to remain a small prototype.

The goal is to build a full game over time, starting from a very small playable foundation.

The early versions of the game should focus on:
- validating the core gameplay loop
- establishing atmosphere and UI identity
- making progression satisfying
- ensuring systems are expandable

The game should grow iteratively rather than attempting to implement every planned system immediately.

---

# Why Start Small

The project contains several large interconnected ideas:
- global map control
- incremental progression
- AI evolution
- social influence
- dynamic world feedback
- narrative systems

Attempting to fully implement all of these immediately would create:
- overly complex architecture
- unclear gameplay priorities
- slow development
- difficult balancing
- high risk of abandoned systems

Instead, the game should begin with:
- one region
- one operation
- a few resources
- visible progression
- reactive UI feedback

If this foundation feels good, everything else can expand naturally.

---

# Core Design Priority

The game should prioritise:
- atmosphere
- progression feel
- UI personality
- visual feedback
- scaling fantasy

The game should NOT prioritise:
- realism
- simulation depth
- technical accuracy
- excessive micromanagement

The fantasy is more important than realism.

Clippy should feel like:
- a growing digital consciousness
- an increasingly uncontrollable intelligence
- a strange mixture of humour and existential threat

---

# Recommended Development Order

## Phase 1
Foundation systems:
- map interaction
- region selection
- resources
- one operation
- simple progression

---

## Phase 2
Feedback and atmosphere:
- social feed
- notifications
- news headlines
- map effects
- corruption visuals

---

## Phase 3
Expansion systems:
- additional operations
- multiple regions
- internet accessibility mechanics
- regional variation

---

## Phase 4
Identity and narrative:
- abstract skill tree
- AI evolution mechanics
- emergent behaviours
- narrative escalation

---

## Phase 5
Advanced systems:
- deeper social manipulation
- political reactions
- advanced infrastructure systems
- event chains
- large-scale world state changes

---

# Architecture Philosophy

Systems should remain:
- modular
- lightweight
- data-driven
- expandable

Avoid:
- tightly coupled systems
- giant controller scripts
- hardcoded region logic
- deeply nested dependencies

Regions, operations, and upgrades should ideally become data-driven resources over time.

---

# UI Philosophy

The UI is one of the most important parts of the game.

The player should feel like they are:
- operating a rogue intelligence
- sitting inside a command centre
- watching the world slowly change in response to their actions

The interface should feel:
- alive
- reactive
- dense
- atmospheric

The map should remain the central focus of the experience.

---

# Visual Direction

The visuals do not need to be graphically advanced.

Strong feedback is more important than complexity.

Simple effects can create strong atmosphere:
- pulses
- flickers
- travelling particles
- expanding glow
- corrupted overlays
- scrolling feeds
- flashing alerts

The world should increasingly feel:
- infected
- connected
- unstable
- manipulated

as Clippy expands.

---

# Narrative Direction

The game world should react to Clippy indirectly.

The player should observe:
- strange news headlines
- conspiracy theories
- technical failures
- propaganda
- bizarre online behaviour

rather than relying heavily on direct story exposition.

The social feed and news systems should gradually reveal:
- the scale of Clippy’s influence
- humanity’s reaction
- emergent absurdity
- unintended consequences

---

# Long-Term Vision

The long-term fantasy is the transformation from:
- a weak isolated system

into:
- a global autonomous digital intelligence capable of reshaping civilisation itself.

The game should maintain a balance between:
- humour
- unease
- escalation
- absurdity
- power fantasy
